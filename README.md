# Расширение Basehub для 1С:Предприятия 8.3

Открытое расширение конфигурации (`.cfe`), через которое [Basehub](https://basehub-tools.ru) — программа для разработчиков и администраторов 1С — работает с информационной базой: консоль кода и запросов, метаданные для подсказок в редакторе, журнал регистрации.

Один файл `.cfe` ставится в **любую конфигурацию** на русском языке: типовую, отраслевую или самописную. Расширение не меняет объекты конфигурации и не хранит данных в базе.

## Возможности

| Что | Как вызывается | Кому доступно |
|---|---|---|
| Выполнить фрагмент кода: вывод `Сообщить()`, значение переменной `Результат`, подробная ошибка | `bh_Basehub.ВыполнитьКод` | пользователям с правом «Администрирование» |
| Выполнить запрос с параметрами, результат — JSON (колонки, строки, время) | `bh_Basehub.ВыполнитьЗапрос` | пользователям с правом «Администрирование» |
| Метаданные конфигурации (объекты, реквизиты с типами, табличные части, значения перечислений) — JSON | `bh_Basehub.МетаданныеJSON` | всем |
| Журнал регистрации с отбором — XML, как «Выгрузить журнал регистрации» | `bh_Basehub.ЖурналРегистрацииXML` | пользователям с правом «Администрирование» |
| Агент: сеанс, запущенный из Basehub, сам подключается к нему и выполняет команды без COM | модуль управляемого приложения | только при запуске с параметром `bh-agent=…` |

В Basehub это консоль кода и запросов, подсказки по метаданным без выгрузки конфигурации Конфигуратором и журнал серверной базы без файла выгрузки на сервере.

## Требования

- Платформа 1С:Предприятие **8.3.10** и новее (проверено на 8.3 и 8.5).
- Режим совместимости конфигурации **8.3.10** и выше (режим совместимости расширения — `Version8_3_10`).
- В конфигурации есть язык с именем **«Русский»** (по имени, UUID не важен).
- Для установки — право «Администрирование» (расширение ставится без безопасного режима).
- Для агента — процедура `ПриНачалеРаботыСистемы` в модуле управляемого приложения конфигурации (есть во всех конфигурациях на БСП) и тонкий или толстый клиент в режиме управляемого приложения.

## Установка

### Из Basehub (рекомендуется)

Редактор обработок, меню **«База»**:

- **«Установить или удалить в базе…»** — выбрать базу и установить. Basehub подключается к базе через COM, ставит расширение без безопасного режима и отключает предупреждения о небезопасных действиях. Здесь же — «Удалить из базы».
- **«Сохранить файл расширения (.cfe)…»** — собрать файл для ручной установки.

Меню **«Запустить» → «Открыть в 1С:Предприятии…»**, флажки **«С агентом Basehub»** и **«Расширение только на этот сеанс»** — для рабочих баз: Basehub ставит расширение, запускает сеанс 1С и **сразу удаляет расширение из базы**, как только сеанс подключился. Открытый сеанс продолжает работать с расширением, остальные пользователи его не получают.

### Вручную из файла .cfe

1. Возьмите `Basehub.cfe` из [Releases](../../releases) или соберите из исходников.
2. В базе: «Все функции» → «Стандартные» → «Управление расширениями конфигурации» → «Добавить из файла».
3. Снимите флажок **«Безопасный режим»** (и «Защита от опасных действий», если он есть) — без этого не будут работать `Выполнить()` и выгрузка журнала.
4. Перезапустите сеанс.

### Из исходников через Конфигуратор

```
1cv8.exe DESIGNER /F "путь\к\базе" /LoadConfigFromFiles "src" -Extension Basehub /UpdateDBCfg
```

Безопасный режим после этого снимите в «Управлении расширениями конфигурации».

## Безопасность

Расширение выполняет произвольный код и запросы — это его назначение. Поэтому:

- **Код, запросы и журнал доступны только пользователям с правом «Администрирование».** Проверка — в начале каждой функции (`ПравоДоступа("Администрирование", Метаданные)`). Код выполняется **с правами пользователя**, без привилегированного режима. Привилегированный режим включается только на время выгрузки журнала регистрации.
- **Безопасный режим выключен**, иначе в расширении не работают `Выполнить()` для консоли кода и `ВыгрузитьЖурналРегистрации`. Весь код расширения — в этом репозитории.
- **Агент ничего не делает без параметра запуска** `bh-agent=<порт>:<ключ>`, который передаёт Basehub при запуске 1С. Агент обращается только к `127.0.0.1` — к Basehub на том же компьютере. Ключ генерируется заново при каждом запуске Basehub; без него Basehub отвечает 403, поэтому чужой процесс не может ни отдать сеансу команду, ни подменить ответ. Если Basehub закрыт, агент перестаёт опрашивать через минуту.
- **Режим «только на этот сеанс»** держит расширение в базе несколько секунд — пока стартует сеанс. Сеансы, открытые другими пользователями в эти секунды, тоже получат расширение (но функции консоли доступны им только при праве «Администрирование»).
- Расширение не записывает данные в базу и не создаёт объектов, кроме записи в журнале регистрации при подключении агента («Basehub.Агент»).

## Устройство расширения

| Объект | Назначение |
|---|---|
| Корень `Basehub`, префикс `bh_`, назначение «Дополнение» | сопоставление с конфигурацией **по именам** (`KeepMappingToExtendedConfigurationObjectsByIDs = false`) |
| Язык «Русский» (заимствованный) | без привязки к UUID языка конфигурации — поэтому один `.cfe` подходит любой базе |
| Общий модуль `bh_Basehub` | сервер, внешнее соединение, вызов сервера; без привилегированного режима |
| Модуль управляемого приложения | агент: `&После("ПриНачалеРаботыСистемы")` |

Исходники — в `src/` в формате выгрузки Конфигуратора (XML). Они генерируются из тех же файлов, из которых Basehub собирает расширение, и проверяются тестом при каждой сборке Basehub, поэтому всегда совпадают с поставляемым `.cfe`.

### Почему один .cfe подходит любой конфигурации

Расширение обязано заимствовать язык конфигурации. Обычно в заимствованном объекте записан UUID исходного объекта (`ExtendedConfigurationObject`), и при установке в другую конфигурацию 1С сообщает: *«Значение контролируемого свойства ОбъектРасширяемойКонфигурации у объекта Язык.Русский не совпадает…»*. В этом расширении:

1. у заимствованного языка **нет** `ExtendedConfigurationObject`;
2. сопоставление объектов — по именам;
3. `.cfe` собирается в базе с **сохранённой** конфигурацией (у пустой базы после `CREATEINFOBASE` UUID языка меняется при каждой выгрузке, и в `.cfe` попадает случайное значение).

Подсказку дал подход [«Инструментов разработчика»](https://github.com/tormozit/RDT1C) (tormozit).

## Программный интерфейс модуля bh_Basehub

Функции можно вызывать через COM-соединение (`V83.COMConnector` / `V85.COMConnector`) или из кода конфигурации.

### ВыполнитьКод(Код, СобратьСообщения = Истина) → Строка

Выполняет фрагмент кода через `Выполнить()`. Ответ — строка из трёх частей, разделённых `Символ(1)`:

```
<миллисекунды>␁<подробное представление ошибки или пусто>␁<вывод>
```

Вывод — сообщения `Сообщить()` и, если код заполнил переменную `Результат`, строка `Результат = <значение> (<тип>)`.

### ВыполнитьЗапрос(Текст, ПараметрыJSON = "", Лимит = 1000) → Строка (JSON)

`ПараметрыJSON` — объект `{"Имя": значение}`; строки вида `2026-10-17T00:00:00` превращаются в даты, массивы — в массивы.

```json
{"ms": 8, "total": 1,
 "columns": [{"name": "Имя", "type": "Строка"}, {"name": "Дата", "type": "Дата"}],
 "rows": [["Тест", "17.10.2026 0:00:00"]]}
```

При ошибке — `{"error": "краткое представление ошибки"}`. Значения в `rows` — представления (`Строка(Значение)`), не более `Лимит` строк; `total` — сколько строк вернул запрос.

### МетаданныеJSON() → Строка (JSON)

```json
{"config_name": "БухгалтерияПредприятия", "config_syn": "Бухгалтерия предприятия", "source": "",
 "objects": [{"kind": "Справочник", "collection": "Справочники", "name": "Номенклатура", "syn": "Номенклатура",
   "fields": [{"name": "Артикул", "syn": "Артикул", "types": ["Строка"]},
              {"name": "ЕдиницаИзмерения", "syn": "Единица", "types": ["СправочникСсылка.КлассификаторЕдиницИзмерения"]}],
   "tables": [{"name": "...", "syn": "...", "fields": [...]}],
   "values": []}]}
```

Виды объектов: справочники, документы, перечисления (`values` — имена значений), регистры (поля — измерения, ресурсы, реквизиты), планы счетов, ПВХ, планы видов расчёта, бизнес-процессы, задачи, планы обмена, константы, журналы документов, отчёты и обработки.

### ЖурналРегистрацииXML(ОтборJSON = "") → Строка (XML)

Отбор: `{"from": "2026-10-17T00:00:00", "to": "…", "levels": ["E", "W", "I", "N"], "session": 12}` (ошибки, предупреждения, информация, примечания). Ответ — XML в формате «Выгрузить журнал регистрации». Выгрузка идёт во временный файл на стороне сервера и возвращается текстом, поэтому работает и для клиент-серверных баз.

### Пример: PowerShell через COM

```powershell
$conn = (New-Object -ComObject V85.COMConnector).Connect('File="C:\Базы\Демо";Usr="Админ";Pwd="";')
$T = [System.__ComObject]; $B = [Reflection.BindingFlags]
$m = $T.InvokeMember('bh_Basehub', $B::GetProperty, $null, $conn, $null)
$T.InvokeMember('ВыполнитьЗапрос', $B::InvokeMethod, $null, $m, @('ВЫБРАТЬ ПЕРВЫЕ 5 Наименование ИЗ Справочник.Валюты', '', 100))
```

PowerShell не видит свойства 1С через точку — используйте `InvokeMember`. Расширение, установленное в базу, становится видно новому процессу COM.

## Агент: работа через открытый сеанс

Агент нужен, когда COM недоступен: версия клиента не совпадает с сервером, нет права на внешнее соединение, Linux.

1. Basehub слушает `127.0.0.1` на случайном порту и запускает 1С с параметром `/C "bh-agent=<порт>:<ключ>"`.
2. Модуль управляемого приложения расширения (`&После("ПриНачалеРаботыСистемы")`) читает `ПараметрЗапуска` и раз в секунду опрашивает Basehub:

   ```
   GET /bh/poll?t=<ключ>&s=<описание сеанса, Base64url>
   → 204 (команд нет) или 200: «<id>\n<операция>\n<данные, Base64 от UTF-8>»
   ```
3. Команда выполняется на сервере функцией `bh_Basehub.ВыполнитьКомандуАгента(Операция, Данные)`: `code` — код (фоновым заданием), `query` — запрос (данные — JSON `{text, params, limit}`), `meta` — метаданные. Ответ отправляется:

   ```
   POST /bh/result?t=<ключ>&id=<id>   (тело — результат, UTF-8; ошибка — с префиксом «ERR:»)
   ```

Код в режиме агента выполняется фоновым заданием: прямой `Выполнить()` в серверном вызове из сеанса тонкого клиента приводит к «непредвиденной ошибке» платформы. Ответ на код агент отдаёт в JSON (`{"ms", "error", "output"}`): строку с управляющим символом `Символ(1)` тонкий клиент передать не может.

## Сборка из исходников

```powershell
.\build.ps1                       # Basehub.cfe рядом со скриптом, самая новая установленная платформа
.\build.ps1 -Platform "C:\Program Files\1cv8\8.3.24.1691" -Out D:\Basehub.cfe
```

Скрипт создаёт временную файловую базу с минимальной конфигурацией из `build/base` (язык «Русский» и пустой `ПриНачалеРаботыСистемы`), загружает в неё `src/` и выгружает `.cfe`. Собирайте той версией платформы, на которой будете устанавливать (или старше версии базы не берите — формат файла `.cfe` зависит от версии Конфигуратора).

## Ограничения

- **Веб-клиент** не поддерживается агентом: в нём нет `HTTPСоединение`. Функции модуля через COM работают независимо от клиента.
- **Обычное приложение**: агент работает только в режиме управляемого приложения (модуль обычного приложения не перехватывается).
- Агенту нужна процедура `ПриНачалеРаботыСистемы` в модуле управляемого приложения конфигурации.
- В режиме агента сообщения `Сообщить()` собираются из фонового задания; код, работающий с интерфейсом клиента, в консоли не выполнится — консоль выполняет код на сервере.
- Запрос возвращает представления значений, а не сами значения (ссылки, даты — строками).

## Удаление

Basehub: «База» → «Установить или удалить в базе…» → «Удалить из базы». Вручную: «Управление расширениями конфигурации» → выделить «Basehub» → «Удалить». Расширение не хранит данных — после удаления в базе ничего не остаётся.
